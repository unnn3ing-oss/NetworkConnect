# 實機驗證清單

自動測試用假的 prober、假的 go2rtc 與 Playwright 的 Chromium，**無法取代**下面這些項目。請在家用真實設備驗證，結果（通過／不通過＋現象）直接勾選並寫在旁邊，回報給開發者。

Mac 與 Windows 各跑一輪；標註「兩者」的項目兩個平台都要做。

## A. 安裝與放行

- [ ] Mac：下載 `.dmg` → 拖進「應用程式」→ 第一次開啟被擋 → 「系統設定 → 隱私權與安全性 → 強制打開」後可啟動
- [ ] Mac：若顯示「已損毀」，執行 `xattr -cr /Applications/NetworkConnect.app` 後可啟動
- [ ] Windows：執行安裝程式 → SmartScreen「其他資訊 → 仍要執行」→ 安裝完成並啟動
- [ ] 兩者：[安裝教學頁](install/index.html) 的每一步畫面與實際畫面一致（文字、按鈕名稱、位置）
- [ ] 兩者：第一次啟動自動進入首次導覽，六步驟都可走完，導覽的「前往…」按鈕都能到對應頁面，總覽的「繼續導覽」能回來

## B. 系統權限與防火牆

- [ ] Mac：第一次偵測區網設備時跳出「區域網路」權限詢問，按允許後設備變為上線
- [ ] Mac：到「隱私權與安全性 → 區域網路」關閉權限 → 所有設備顯示離線，狀態頁出現「到系統設定開啟區域網路」提示；重新開啟後恢復
- [ ] 兩者：防火牆詢問「允許傳入連線」，允許後手機可以連上；按拒絕時手機連不上（確認不會影響這台電腦自己的視窗）
- [ ] 兩者：手機連線（選單的「手機連線」顯示的網址與 QR Code）掃描後可開啟，且只有同一個 Wi-Fi 下才連得到

## C. 常駐與系統整合

- [ ] 兩者：關閉視窗後程式縮到選單列／系統匣，偵測持續（關視窗 10 分鐘後，把一台設備拔網路線，仍會收到離線通知）
- [ ] Windows：第一次關閉視窗時出現一次說明通知，之後不再出現
- [ ] 兩者：從選單「結束 NetworkConnect」才會真正結束
- [ ] Windows：結束 App 後，**工作管理員**確認沒有殘留的 `go2rtc.exe` 與 `NetworkConnect` 行程
- [ ] Mac：結束 App 後，「活動監視器」確認沒有殘留 `go2rtc`
- [ ] 兩者：強制結束 App（工作管理員／強制結束）後重新開啟，不會有兩個 go2rtc，監視器頁仍可播放
- [ ] 兩者：選單「開機自動啟動」打開 → 重新開機後自動啟動並縮到選單列／系統匣；關閉後不再自動啟動
- [ ] 兩者：選單「暫停偵測 30 分鐘」後，狀態頁顯示暫停橫幅，期間拔掉設備不會通知，30 分鐘後自動恢復
- [ ] 兩者：關鍵設備離線與恢復都有系統通知；同一台 5 分鐘內最多一次；非關鍵設備離線不通知
- [ ] 兩者：**設了存取密碼之後**，桌面通知仍然正常（通知由主行程發出，不受登入影響）；視窗與手機都需要登入，登入後正常
- [ ] 兩者：電腦睡眠後喚醒，偵測自動恢復，不會一堆設備誤報離線後又上線
- [ ] 兩者：電腦斷電／強制關機後重新開機，App（若有設開機自動啟動）自動恢復，資料完整，設備、樓層、平面圖、NVR 都在

## D. 偵測

- [ ] 真實 ping：家中每一類設備（路由器、交換器、基地台、NAS、電腦、攝影機）都能正確判定上線
- [ ] 拔掉一台設備電源／網路線：約 3 個偵測週期後變離線；接回後恢復上線
- [ ] 手機休眠時會不會被誤判離線？記錄各手機（iPhone／Android）的實際表現，必要時改用 TCP 或「不偵測」
- [ ] 偵測方式 TCP（例如 NAS 的 5000／443）、HTTP（例如路由器管理頁）各試一台
- [ ] 同時偵測 30 台以上設備時，這台電腦的 CPU 與網路沒有明顯負擔

## E. 手機與瀏覽器

- [ ] iPhone Safari：所有分頁可開啟、可操作，沒有版面跑掉或橫向捲動
- [ ] Android Chrome：同上
- [ ] 手機的深色模式／淺色模式切換後，各頁顏色與對比正常（燈號、卡片、導覽）
- [ ] 電腦瀏覽器（Chrome／Safari／Edge）深色模式同上
- [ ] 平面圖：iPhone Safari 與 Android Chrome 上**雙指縮放**順暢，不會連整個網頁一起縮放
- [ ] 平面圖：手機上**長按設備點**可以移除（出現確認對話框）
- [ ] 平面圖：手機上**點清單中的設備，再點圖**可以放置；放置後重新整理位置不變
- [ ] 平面圖：手機上拖曳平移不會誤觸設備點

## F. NVR 與監視器

逐一驗證你家有的品牌（模板的 RTSP 路徑需實機確認）：

- [ ] Hikvision：精靈測試成功，主碼流與子碼流都能播放
- [ ] Dahua／Imou／Amcrest：同上
- [ ] Uniview：同上
- [ ] Reolink：同上
- [ ] 自訂 RTSP 網址：同上
- [ ] 子碼流是 **H.265** 時：精靈的測試步驟顯示「請將子碼流改為 H.264」警告；記錄 **Chrome 與 Safari** 實際的表現（黑畫面？卡頓？能播？）
- [ ] 把 NVR 子碼流改為 H.264 後：Chrome 與 Safari 都能順暢播放
- [ ] **iPhone 沒有 MSE 時的回退播放**：iPhone Safari 開監視器頁，確認會自動回退（WebRTC／HLS 等）並能播放；記錄延遲與是否穩定
- [ ] **NVR 最大同時連線數**：9 路同看時，NVR 本身是否拒絕連線或掉線？記錄你的 NVR 型號與實際可同時看幾路；必要時調低「同時串流上限」
- [ ] **帳密含特殊字元**（例如密碼含 `@ # : /` 或 `%`）：用真實 NVR 完成測試連線與播放
- [ ] **NVR 斷線後自動重連**：拔掉 NVR 網路線 30 秒再接回，畫面牆自動恢復，不需要重新整理
- [ ] 把 NVR 關機再開機，監視器頁顯示錯誤提示，開機後恢復
- [ ] 9 路同看（9 分割）：記錄這台電腦的 CPU 使用率與網路頻寬；手機同時觀看時是否順暢
- [ ] 切換分頁、切換到別的瀏覽器分頁、鎖定手機螢幕後，到 NVR 或 go2rtc 確認串流連線數降為 0；回來後恢復
- [ ] 雙擊單一畫面開全螢幕（預設子碼流），按「切換為主碼流」可切換；工具列按鈕在黑底上清楚可見

## G. 資料

- [ ] 匯出 JSON（含平面圖）→ 在另一台電腦安裝後匯入 → 設備、樓層、平面圖、位置、NVR 都還原；含密碼匯出時 NVR 可直接連線
- [ ] 把舊 Google Sheet「設備清單」匯出 CSV 後匯入：類別對應、上游關係、位置都正確，未對應的列在報告中
- [ ] 設定頁改模組開關後，重新啟動 App 才生效；停用 NVR 後其他分頁都正常
